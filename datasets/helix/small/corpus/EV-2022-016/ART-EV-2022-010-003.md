# ADR-2022-016: Hybrid API Strategy for Helix Module

## Status
Accepted

## Date
2022-07-20

## Authors
Arjun Mehta, Daniel Smith

## Context
Helix Logistics is expanding its platform to support a new Helix module that will serve mid‑market freight‑forwarding partners. Existing partner integrations rely heavily on a stable RESTful API, while internal teams require more flexible data fetching for rapid feature iteration. During a design review on 20 July 2022, Arjun advocated for a pure RESTful approach to preserve backward compatibility, whereas Daniel pushed for GraphQL to enable efficient internal queries.

## Decision
We will adopt a hybrid API strategy: expose a RESTful endpoint for all external partners, ensuring backward compatibility and minimal disruption to legacy integrations. Internally, the Helix module will use GraphQL to allow flexible, efficient data retrieval. This approach balances partner stability with internal agility. ⚙️

## Alternatives Considered
### Pure RESTful API
A single RESTful interface would maintain backward compatibility but limit internal flexibility, forcing workarounds for complex queries and increasing payload size.

### Pure GraphQL
GraphQL would provide internal flexibility but break existing partner contracts and require significant changes to partner integrations, risking churn.

### Hybrid
Combines the strengths of both: external partners use REST, internal services use GraphQL. This mitigates risks while enabling rapid development.

## Consequences
Positive: Partners retain stable API contracts; internal teams gain flexible data access, reducing development time. Negative: Increased operational complexity—two API gateways, versioning, and documentation. Requires coordination between product and engineering teams to maintain consistency.
