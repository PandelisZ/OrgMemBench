# API Strategy Clarification — 2022-07-20

**Attendees:** Arjun Mehta, Daniel O'Connor  
**Note-taker:** Daniel O'Connor

## Agenda

- Review the 2021-06-18 API design disagreement  
- Clarify current stance on REST vs GraphQL  
- Update Product Playbook and engineering communication

## Discussion

- **Arjun:** “We had a misunderstanding about the spec. I thought we were leaning toward a pure REST approach for core CRUD, while you were pushing GraphQL for analytics.”  
- **Daniel:** “Exactly. The original note from 2021-06-18 had us prototyping both, but that was based on a misinterpretation of the spec. We now see that a hybrid model actually satisfies both performance and flexibility goals.”  
- **Arjun:** “So we’re not abandoning either paradigm; we’re combining them.”  
- **Daniel:** “Yes, that’s the plan. I’ll draft the update for the Product Playbook and circulate it to the engineering team.”  
- **Arjun:** “Let me know if that’s acceptable. I’ll coordinate with the dev ops lead to ensure the deployment pipeline supports both endpoints.”  
- **Daniel:** “Just a quick reminder that this clarification supersedes the earlier 2021 decision. We now understand that the hybrid approach is the correct path forward.”  
- **Arjun:** “Thanks for the update. I’ll add a note to the sprint backlog.”

## Decisions

- Adopt a hybrid API strategy: core CRUD operations remain RESTful; complex data retrieval will use GraphQL.  
- Update the Product Playbook to reflect this hybrid approach.  
- Communicate the change to the engineering team.
