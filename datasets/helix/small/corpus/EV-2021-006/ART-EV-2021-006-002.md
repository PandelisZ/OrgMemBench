# API Architecture Debate — 2021-06-18

**Attendees:** Arjun Mehta, Daniel Ortiz, Maya Patel, Ravi Kumar  
**Note-taker:** Daniel Ortiz

## Agenda

- Review current shipment status API design
- Discuss potential GraphQL layer for analytics
- Decide on prototyping approach

## Discussion

- **Arjun** opened with, “We’ve been using a simple REST endpoint for status checks for months. It’s straightforward and the team knows it.”  
- **Daniel** countered, “But the analytics dashboard needs to pull a lot of related data. A GraphQL layer could let us fetch exactly what we need without over‑fetching.”  
- **Maya** suggested, “Maybe we can prototype both and measure performance.”  
- **Ravi** added, “Also think about developer experience—new hires will be more comfortable with REST if we keep it simple.”  
- **Daniel** emphasized, “Testing is a mindset; we should cover edge cases in both prototypes.”  
- **Arjun** agreed, “Let’s split the work: I’ll lead the REST prototype, you build the GraphQL schema.”  
- **Maya** noted, “Automation saves time—let’s set up CI for both.”  

## Decisions

- Prototype a lightweight RESTful endpoint for the core shipment status API.  
- Build a GraphQL schema for the analytics dashboard.  
- Evaluate performance and developer experience before committing to a single architecture.
