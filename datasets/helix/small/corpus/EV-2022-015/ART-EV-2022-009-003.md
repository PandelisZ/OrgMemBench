# Postmortem: 2022-08-30 Database Migration Failure — 2022-09-20

**Incident date:** 2022-09-15  
**Severity:** SEV-2  
**Authors:** Omar Farah, Omar Al-Zahra, Daniel O'Connor  
**Status:** Final  

## Summary

Just a quick note: the 2022-08-30 database migration failed because a required schema migration script was omitted from the deployment package. The failure caused a temporary outage of the production database, impacting all mid‑market freight‑forwarding customers for approximately 1.5 hours. Automated tests detected the issue, and the incident was resolved by rolling back to the previous schema and redeploying with the missing script. Let me know if that works. Thanks for the update.  

## Timeline

- 14:00 — Automated migration test failed, alert sent to DevOps.  
- 14:05 — Incident ticket created in Jira, team notified.  
- 14:15 — Engineering team began investigation; identified missing migration script.  
- 14:30 — Root cause confirmed; rollback plan initiated.  
- 15:00 — Database rolled back to previous stable schema.  
- 15:30 — Missing migration script added to deployment package.  
- 15:45 — Redeployment executed; health checks passed.  
- 16:00 — Service restored; monitoring returned to normal.  

## Root cause

The migration failure was caused by a missing schema migration script in the deployment package. The script, which added a critical column to the `orders` table, was inadvertently omitted during the packaging process. Because the CI pipeline did not include a verification step to ensure all migration scripts were present, the deployment proceeded without the necessary changes, leading to a schema mismatch and database errors.  

## Contributing factors

- Lack of automated verification for migration scripts in the CI pipeline.  
- No formal rollback plan for database migrations at the time of the incident.  
- Insufficient code review coverage for migration scripts, allowing the omission to go unnoticed.  

## What went well

- Rapid detection by automated tests and alerting.  
- Quick escalation to the engineering team and clear communication via Jira.  
- Successful rollback and restoration of service within 1.5 hours.  

## What went poorly

- The missing migration script was not caught by any pre‑deployment checks.  
- Absence of a documented rollback plan delayed the initial response.  
- Limited visibility into the migration packaging process contributed to the oversight.
