# Incident: Database migration failure — INC-2022-09-15-01

**Status:** Investigating  
**Severity:** SEV-3  
**Started:** 2022-09-15 10:12  
**Resolved:** TBD  
**Customer impact:** Mid‑market freight‑forwarding clients experienced a brief outage of the order‑processing API; no data loss, but some requests timed out.  
**Incident commander:** Omar Al‑Zahra  

## Current understanding

The 2022‑08‑30 schema migration failed because a required migration script was omitted from the deployment package. The failure caused the database to reject new schema changes, leading to API timeouts for all active sessions.  

## Timeline (live‑updated)

- 10:12 – Migration job started on staging; logs show missing `V20220830__add_new_table.sql`.  
- 10:15 – Automated health check flagged `DB_SCHEMA_MISMATCH`.  
- 10:18 – Incident commander notified; rollback to previous schema initiated.  
- 10:22 – Rollback succeeded; API responses back to normal.  

## Mitigation

- Paused the production deployment until the missing script is added.  
- Rolled back to the last stable schema version to restore service.  
- Added a quick manual check in the CI pipeline to verify all migration scripts are present before promotion.  

## Customer comms

- 10:20 – Sent an internal Slack alert to the support team.  
- 10:25 – Customer‑facing status page updated: “We’re experiencing a temporary outage due to a database migration issue. Our team is working on a fix.”  

## Next update

- 10:30 – Awaiting confirmation that the missing script has been added and the new migration passes CI.  
- 11:00 – Will provide a full post‑mortem once the issue is fully resolved.
