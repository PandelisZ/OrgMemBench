# Incident Review – Load Balancer Outage  
2023-02-15

**Attendees:** Ethan Brooks, Emily Zhao, Nia Osei  
**Note-taker:** Emily Zhao

## Agenda

## Discussion
- **Ethan:** “We saw a 30‑minute outage on the customer portal because the new LB rule was pointing to a de‑provisioned backend.”  
- **Emily:** “The config diff shows the `backend_pool` was set to `prod‑old‑svc` instead of `prod‑new‑svc`. That’s the root cause.”  
- **Nia:** “If we roll back the LB config, traffic will route correctly again. We can patch the typo in the next deploy.”  
- **Ethan:** “Let’s do a quick rollback and push a hotfix. We’ll also flag the alerting rule so we get a warning next time.”  
- **Emily:** “I’ll draft the hotfix PR and update the docs. We should schedule a post‑mortem for next week.”  
- **Nia:** “Can we add a check in the CI pipeline to validate backend names?”  
- **Emily:** “Sure, I’ll add that. Component ready.”  

## Decisions
- Roll back the load balancer configuration to the previous stable state.  
- Deploy a hotfix correcting the misconfiguration.  
- Schedule a post‑mortem to update documentation and alerting rules.
