# Incident: Real‑time Tracking API Outage — INC-2023-07-12-01

**Status:** Identified  
**Severity:** SEV-2  
**Started:** 2023-07-12 14:00  
**Resolved:** TBD  
**Customer impact:** 12 customers experienced stale data and timeouts on the real‑time tracking API.  
**Incident commander:** Ethan Brooks  

## Current understanding

The API is timing out and returning stale data due to a race condition introduced by the new caching layer in the latest deployment. Concurrent requests are hitting the cache before it is fully populated, causing timeouts and incorrect responses.

## Timeline (live‑updated)

- 14:00 — Outage detected by monitoring; API health checks failing.  
- 14:05 — Ethan and Nia coordinate rollback to the previous stable deployment.  
- 14:10 — Hotfix applied to the API service to guard against the race condition.  
- 14:20 — Redeploy of the corrected version.  
- 14:30 — Temporary fallback endpoint enabled for affected customers.  
- 14:35 — Customer communication drafted and sent to TransLink Logistics and the other 11 customers.  

## Mitigation

- **Rollback** to the last known good deployment (successfully completed).  
- **Hotfix**: added a lock around cache population to prevent concurrent writes.  
- **Fallback**: enabled a read‑through endpoint that bypasses the cache for critical requests.  
- **Monitoring**: increased alert thresholds for API latency and error rates.  

## Customer comms

- 14:35 — Email sent to TransLink Logistics and 11 other customers explaining the outage, cause, and steps taken.
