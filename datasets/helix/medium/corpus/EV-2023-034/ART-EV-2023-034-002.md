# API Auth Migration Discussion — 2023-04-12

**Attendees:** Daniel Kim, Ethan Brooks, Maya Patel (Security Lead), Luis Gomez (Platform Engineer)  
**Note-taker:** Ethan Brooks

## Agenda

- Review current auth scheme and compliance gaps  
- Propose migration to OAuth 2.0  
- Outline pilot plan for shipping module  
- Update docs & training timeline

## Discussion

- **Daniel:** “We’re still on Basic Auth for the API. With the new data protection regs, that’s a big risk.”  
- **Ethan:** “OAuth 2.0 would give us token‑based auth, better audit trails, and easier revocation.”  
- **Maya:** “From a security standpoint, token scopes will let us enforce least‑privilege per partner.”  
- **Luis:** “We can hook OAuth into our API gateway with minimal code changes. Pilot on shipping module is doable by next sprint.”  
- **Daniel:** “Let’s phase out Basic Auth by Q3. All partners need to switch by end‑of‑quarter.”  
- **Ethan:** “Docs and support training need to be updated before the pilot.”  
- **Maya:** “We should also plan a compliance review after the pilot.”  

## Decisions

- Adopt OAuth 2.0 for Helix API authentication.  
- Phase out Basic Auth by Q3 2023, starting with a pilot on the shipping module.  
- Update all developer docs and support training to reflect the new flow before the pilot.  
- Require all external partners to use OAuth 2.0 by the end of the quarter.

## Action items

- [ ] @Luis: Set up OAuth 2.0 in API gateway and configure shipping module for pilot — by 2023-04-20  
- [ ] @Maya: Draft compliance checklist for post‑pilot review — by 2023-04-25  
- [ ] @Ethan: Update developer docs and send to support team — by 2023-04-22  
- [ ] @Daniel: Coordinate with partner onboarding to communicate new auth requirements — by 2023-04-24  

## Open questions

- How will we handle partners with legacy integrations that can’t switch immediately?  
- What fallback mechanism, if any, should we provide during the transition?
