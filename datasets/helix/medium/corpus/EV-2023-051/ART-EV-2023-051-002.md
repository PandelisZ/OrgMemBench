# Incident: Load Balancer Mis‑config — INC-2023-04-20-01

**Status:** Investigating  
**Severity:** SEV-3  
**Started:** 2023-04-20 10:12  
**Resolved:** TBD  
**Customer impact:** API endpoints were unavailable for ~30 min, causing delayed shipment quotes for several mid‑market freight forwarders.  
**Incident commander:** Ethan Brooks  

## Current understanding

The outage began when the new deployment pushed a new container image to the staging environment. The load balancer was re‑configured to point to the new container group, but the health‑check path was incorrectly set, so the LB stopped routing traffic. This caused a 30‑minute service interruption before the traffic was manually redirected back to the previous stable version.

## Timeline (live‑updated)

- 10:12 — New container image deployed to staging.  
- 10:15 — Load balancer updated to route to new containers.  
- 10:18 — Health‑check failures detected; traffic drops to 0 %.  
- 10:20 — Ethan and Omar notice API unavailability.  
- 10:22 — Rollback initiated to previous stable image.  
- 10:25 — Traffic restored to 100 % on old containers.  
- 10:30 — Service metrics return to normal.  

## Mitigation

- Rolled back the deployment to the last stable image.  
- Updated the load balancer health‑check path to `/healthz`.  
- Restarted the LB configuration to ensure proper routing.  
- Monitored API latency and error rates; all metrics are back to baseline.
