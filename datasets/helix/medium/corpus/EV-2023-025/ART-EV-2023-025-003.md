## Overview  
On **March 15, 2023** (Event ID EV‑2023‑025) the Helix team decided to launch a new self‑service customer portal. The goal was to give our freight‑forwarding clients a single place to manage shipments, view analytics dashboards, and submit tickets—replacing the old manual ticketing workflow. The decision was driven by recurring customer requests for a more efficient interface that would reduce support load and improve shipment visibility.

**Participants**  
- **Nia Osei** (P‑0042) – coordinated the support integration  
- **Emily Zhao** (P‑0040) – implemented the UI components  
- **Ethan Brooks** (P‑0031) – set up the backend API and CI/CD pipeline  

## Implementation  
- **Backend**: Built a RESTful API in Node.js, deployed to our GitLab CI/CD pipeline, and exposed via the new BigQuery‑backed analytics layer.  
- **Frontend**: Emily used Adobe XD to design the UI, then hand‑off to the dev team for implementation in React.  
- **Support Integration**: Nia wired the portal to Salesforce to auto‑create tickets and sync status updates.  
- **Testing**: Fireflies.ai captured all stakeholder meetings; the transcripts were stored in Confluence for traceability.  

## Impact  
- **Client Experience**: Clients can now create, track, and close tickets directly from the portal.  
- **Support Load**: Early metrics show a 30 % drop in inbound support tickets within the first week.  
- **Analytics**: Real‑time shipment dashboards provide visibility that was previously only available via manual reports.  

## Open questions / TODOs  
- Verify that all legacy ticket data is correctly migrated to Salesforce.  
- Monitor API latency under peak load; consider scaling the backend if needed.  
- Gather client feedback on the UI; iterate on the design if usability issues arise.
