# Sprint Retrospective – API Throttling Review — 2023-04-25

**Attendees:**  
- Diego Alvarez (Product Owner)  
- Nia Osei (Customer Success)  
- Alex Kim (Engineering Lead)  
- Maya Patel (QA Lead)  
- Sam Torres (DevOps)

**Note-taker:** Maya Patel

## Agenda
- Review TransLink status delay incident
- Identify root cause
- Propose workflow redesign

## Discussion
- **Nia:** “We’ve been getting the same delay reports from TransLink. Their shipments are stuck in the ‘In Transit’ state for hours.”  
- **Diego:** “We need to understand why the API is throttling. Let’s dig into the logs.”  
- **Alex:** “Our current endpoint hits the rate limit during peak hours. The throttling is causing the delay.”  
- **Sam:** “We can add a new endpoint with higher limits and better caching.”  
- **Maya:** “QA can run a load test on the new endpoint once it’s built.”  
- **Diego:** “Good. Let’s plan the redesign and get it into the backlog.”

## Decisions
- Escalate the TransLink ticket to the product owner for a cross‑functional review.  
- Convene a sprint retrospective to investigate root causes and plan a redesign of the status update workflow.  
- Agree that API throttling is the root cause and a new endpoint will be proposed to improve reliability.
