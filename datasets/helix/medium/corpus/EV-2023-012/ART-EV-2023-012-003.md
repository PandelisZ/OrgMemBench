# Incident Review – API Latency Spike – 2023-02-10

**Attendees:** Ethan Brooks, Daniel Kim, Maya Patel (Product), Luis Gomez (Backend)  
**Note‑taker:** Ethan Brooks

## Agenda
- Quick recap of the 30‑min latency spike  
- Identify root cause and immediate mitigation  
- Plan for hotfix and monitoring improvements  

## Discussion
- **Ethan:** “We saw a 30‑minute window where API latency spiked and shipment orders were failing. The spike happened right after the new caching layer went live.”  
- **Daniel:** “The logs point to a race condition in the cache invalidation logic. Under peak load, multiple requests were trying to update the same cache entry simultaneously.”  
- **Maya:** “That explains why the orders were stuck. We need to roll back to the previous deployment ASAP.”  
- **Luis:** “I can pull the last stable image from GitLab and redeploy. It’ll take about 10 minutes.”  
- **Ethan:** “While that’s happening, let’s schedule a hotfix for the cache logic. We’ll patch the invalidation routine and add a unit test for the race condition.”  
- **Daniel:** “Also, we should add a latency alert to the monitoring stack. That way we’ll catch a similar spike earlier.”  
- **Maya:** “Good idea. I’ll draft the alert rule for the next sprint.”  

## Decisions
- Roll back to the previous stable deployment immediately.  
- Schedule a hotfix to address the cache invalidation race condition.  
- Add a new latency alert to the monitoring stack.
