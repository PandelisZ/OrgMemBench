# Incident: Load Balancer Misconfiguration — INC-2023-10-20-01

**Status:** Identified  
**Severity:** SEV-2  
**Started:** 2023-10-20 14:12  
**Resolved:** 2023-10-20 16:05  
**Customer impact:** API unavailable for 2 hours, causing delayed shipment quotes and order processing failures.  
**Incident commander:** Ethan Brooks

## Current understanding

The API outage began at 14:12 when the new deployment introduced a misconfigured load balancer that stopped routing traffic to the service instances. Traffic was dropping, and health checks were failing across the cluster. The issue was isolated to the load balancer configuration; the application code was unaffected.

## Timeline (live-updated)

- 14:12 — First alerts from CloudWatch: 5xx errors spike, health checks failing.  
- 14:15 — Ethan and Emily Zhao review logs, confirm LB misconfiguration.  
- 14:18 — Rollback initiated: previous stable deployment restored.  
- 14:25 — Traffic resumes, but intermittent failures persist.  
- 14:30 — Patch applied to LB settings (correct listener rules).  
- 14:45 — Circuit breaker deployed to isolate failing service.  
- 15:00 — New monitoring alert added for LB health.  
- 15:30 — Incident playbook updated with quick rollback procedure.  
- 16:05 — Service fully stable, no further errors.

## Mitigation

- Rolled back the recent deployment to the last known good state.  
- Patched the load balancer configuration to correct the listener rules.  
- Deployed a circuit breaker to isolate the failing service and prevent cascading failures.  
- Added a new CloudWatch alarm to detect LB health issues earlier.  
- Updated the incident response playbook to include a quick rollback procedure.
