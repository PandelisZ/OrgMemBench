# Incident: Ticketing System Outage — INC-2023-04-12-01

**Status:** Identified  
**Severity:** SEV-2  
**Started:** 2023-04-12 09:15  
**Resolved:** 2023-04-12 09:45  
**Customer impact:** Ticketing system was unreachable for all users, delaying support response times.  
**Incident commander:** Ethan Brooks

## Current understanding

The load balancer was routing traffic to a stale backend pool, causing the ticketing system to be unreachable. I identified the misconfiguration and reloaded the configuration.

## Timeline (live-updated)

- 09:15 — Ticketing system reported 502 errors.  
- 09:20 — I discovered the load balancer pointing to the wrong backend pool.  
- 09:22 — Reloaded the load balancer configuration.  
- 09:30 — Traffic started flowing correctly; health checks passing.  
- 09:45 — Ticketing system fully operational again.

## Mitigation

Reloaded the load balancer configuration immediately. Added a health‑check monitor for the load balancer to catch similar issues early. Documented the correct configuration in Confluence for future reference.

## Customer comms

- 09:25 — Notified support team via Slack that the issue was identified and being fixed.  
- 09:35 — Sent a status update to the customer portal: “Ticketing system is back online.”

On resolution. Deploying now. Let me know if you spot any issues. Thanks for the support.
