# Incident: 4‑hour API outage — INC-2023-07-12-01

**Status:** Investigating  
**Severity:** SEV-2  
**Started:** 2023-07-12 10:15  
**Resolved:** TBD  
**Customer impact:** API endpoints unavailable for ~4 hrs, causing delayed shipment status updates for mid‑market freight forwarders.  
**Incident commander:** Ethan Brooks  

## Current understanding

We’re seeing a 4‑hour outage on the public API. Initial diagnostics point to a misconfigured load balancer that was routing traffic to a stale backend pool. The balancer’s health‑check probes were disabled, so traffic was still being sent to an unresponsive node.  

## Timeline (live‑updated)

- 10:15 — API traffic spikes, latency increases.  
- 10:20 — Service logs show repeated 502 errors.  
- 10:25 — Ethan and Victor pinged the load balancer config.  
- 10:30 — Misconfiguration identified: backend pool pointing to old instance.  
- 10:35 — Re‑configured balancer to correct pool.  
- 10:40 — Added health‑check probes to all backend nodes.  
- 10:45 — Traffic restored, API responses normal.  

## Mitigation

- Re‑configured the load balancer to point to the correct backend pool.  
- Enabled health‑check probes to prevent future routing to unhealthy nodes.  
- Monitored traffic for 30 min to confirm stability.  

## Customer comms

- 10:30 — Notified internal support that the issue is being investigated.  
- 10:45 — Sent out a status update to affected customers via email and the status page.  

## Next update
