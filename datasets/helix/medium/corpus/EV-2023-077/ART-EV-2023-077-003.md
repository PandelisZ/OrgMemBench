# Incident: Status‑Mapping Regression in Shipment Service — INC-2023-07-25-001

**Status:** Investigating  
**Severity:** SEV-2  
**Started:** 2023-07-25 14:12  
**Resolved:** TBD  
**Customer impact:** TransLink Logistics reported stale shipment status data; some shipments were marked as “In Transit” when they had already been delivered.  
**Incident commander:** Maya Chen (SRE Lead)

## Current understanding

A recent merge introduced a regression in the status‑mapping logic of the shipment microservice. The bug caused the service to return outdated status values for certain shipments, leading to the stale data observed by TransLink Logistics. The issue was first detected by the automated monitoring alert that flagged a spike in status‑update failures.

## Timeline (live‑updated)

- **14:12** – Alert triggered: `shipment_status_mapping_error` spike.  
- **14:13** – Maya Chen notified the support team; Nia Osei confirmed the customer’s complaint.  
- **14:15** – Initial investigation: logs show repeated `status_mapping_error` exceptions for shipment IDs 9876‑1234.  
- **14:18** – Code review identifies the recent merge of `feature/status‑fix` that altered the mapping table.  
- **14:20** – Hotfix branch `hotfix/status‑mapping‑correction` created and deployed to staging.  
- **14:25** – 30‑minute smoke test in staging: status updates now reflect correct values.  
- **14:30** – Hotfix promoted to production.  
- **14:32** – Monitoring alert cleared; status updates normal.  

## Mitigation

- Deployed hotfix to staging, performed smoke test, then promoted to production.  
- Added a new monitoring alert for `status_mapping_error` to catch future regressions early.  
- Scheduled a retrospective with the product team to review the regression and improve merge checks.
