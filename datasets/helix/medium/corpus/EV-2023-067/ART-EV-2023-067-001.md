# Incident: API latency spike on TransLink endpoint — INC-2023-04-20-01

**Status:** Investigating  
**Severity:** SEV-2  
**Started:** 2023-04-20 09:12  
**Resolved:** TBD  
**Customer impact:** TransLink Logistics experienced API latency > SLA (200 ms) on the `/orders/submit` endpoint, causing delayed order processing.  
**Incident commander:** Nia Osei

## Current understanding

The spike began at 09:12 UTC. Initial metrics show a 4× increase in requests to `/orders/submit` over the past 5 minutes, correlating with a new feature rollout earlier that day. Database query times for the `orders` table have risen to 350 ms, exceeding the 200 ms SLA.

## Timeline (live‑updated)

- 09:12 — Latency alert triggered for `/orders/submit`.  
- 09:13 — Nia Osei escalated the issue to engineering.  
- 09:14 — Emily Zhao begins investigation, identifies high‑volume endpoint as culprit.  
- 09:15 — Emily applies temporary throttling rule (max 200 req/min) to the endpoint.  
- 09:16 — Latency drops to 180 ms; monitoring shows improvement.  
- 09:17 — Emily adds Redis cache layer for order lookups.  
- 09:18 — Latency stabilizes below SLA; new monitoring alert configured for the endpoint.

## Mitigation

- **Throttling:** Applied a temporary rate limit to reduce load on the database.  
- **Caching:** Implemented Redis caching for frequent order queries, reducing DB contention.  
- **Alerting:** Added a new alert rule for `/orders/submit` latency > 200 ms.  

Both measures are holding; latency remains within SLA.
