# API Latency Review — 2023-04-20

**Attendees:** Nia Osei, Emily Zhao, Raj Patel, Maya Lin  
**Note-taker:** Emily Zhao

## Agenda

- Review recent spike in API latency from TransLink
- Identify root cause and immediate mitigation
- Plan long‑term monitoring and capacity adjustments

## Discussion

- **Nia:** “We got a ticket from TransLink about a 2‑second latency spike on the new shipment‑status endpoint. It’s over our SLA.”  
- **Emily:** “I pulled the metrics. The endpoint was hit 5× the usual traffic after the last deployment. The DB query plan shows a full table scan.”  
- **Raj:** “That endpoint was added last sprint to expose real‑time status. We didn’t add any cache layer yet.”  
- **Maya:** “Could we throttle the requests temporarily? Maybe a rate limit of 100 req/s for that path?”  
- **Nia:** “Let’s do that while we figure out a permanent fix. Also, we should add a new alert for this endpoint.”  
- **Emily:** “I’ll add a Redis cache wrapper around the DB call. That should reduce contention.”  
- **Raj:** “Once we have the cache, we can re‑evaluate the query plan and maybe add an index.”  
- **Maya:** “Make sure the alert triggers if latency > 1.5s for more than 5 minutes.”  

## Decisions

- Apply a temporary throttling rule to the shipment‑status endpoint.  
- Add a Redis cache layer for the endpoint’s DB calls.  
- Create a new monitoring alert for latency on this endpoint.
