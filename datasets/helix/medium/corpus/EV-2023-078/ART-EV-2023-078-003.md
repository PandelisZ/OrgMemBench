# API Versioning Policy – Draft (pre‑2023‑07‑30)

> **Last updated:** 2023-07-25  
> **Owner:** Marco Rossi  
> **Status:** Stale  

**Event ID:** EV‑2023‑078  

## Background  
The Helix API contract has historically evolved with only backward‑compatible changes. A new feature introduced a breaking change, sparking a discussion between Marco Rossi (P‑0033) and Maya Chen (P‑0026) about how to version the API moving forward.

## Decision  
We agreed on a hybrid versioning strategy:  
- **Semantic versioning** applies **only** when a change introduces a breaking API contract.  
- All other changes are considered backward‑compatible and will be marked as **patch** or **minor** releases.

## Reason  
- Marco wanted a new major version to clearly signal the breaking change.  
- Maya preferred to keep the contract stable to avoid unnecessary disruption.  
The compromise balances clear communication of breaking changes with minimal impact on downstream consumers.

## Implementation  
- Update the API documentation to reflect the new policy.  
- Communicate the policy to the engineering team via Slack.  
- Document the policy in Confluence on **2023‑07‑30** under the page titled *API Versioning Policy – 2023‑07‑30*.

## Open questions / TODOs

- Review the policy after the next release cycle to ensure it still meets our needs.
