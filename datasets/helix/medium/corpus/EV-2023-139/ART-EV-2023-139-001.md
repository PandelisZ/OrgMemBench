# Incident: Load Balancer Misconfiguration Outage — INC-2023-10-12-01

**Status:** Investigating  
**Severity:** SEV-2  
**Started:** 2023-10-12 14:32  
**Resolved:** TBD  
**Customer impact:** All inbound API traffic to the freight‑forwarding portal was unavailable for ~15 min, causing delayed shipment quotes for several mid‑market clients.  
**Incident commander:** Ethan Brooks

## Current understanding

The new load balancer was deployed with a missing validation step. Ethan misconfigured the routing rules, causing traffic to be dropped. No automated tests or drift alerts were in place, so the error went unnoticed until the first failed health check.

## Timeline (live‑updated)

- 14:32 — Deployment of LB v2.0 initiated via GitLab CI.  
- 14:35 — Health checks start failing; traffic drops to 0 %.  
- 14:36 — Ethan notices the anomaly in the dashboard.  
- 14:37 — Ethan rolls back to LB v1.5.  
- 14:38 — Traffic resumes; API responses back to normal.  
- 14:40 — Patch applied to correct routing rule.  
- 14:41 — Automated validation test added to CI pipeline.  
- 14:42 — Monitoring alert configured for configuration drift.

## Mitigation

- Immediate rollback to the previous stable load balancer configuration.  
- Manual patch applied to correct the misconfiguration.  
- Added automated validation tests to the CI pipeline to catch similar issues in the future.  
- Implemented a configuration drift alert that will notify the DevOps team if the load balancer changes again.
